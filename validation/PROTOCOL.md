# OpenVQ validation candidate protocol

Candidate source is frozen at the commit used by this validation branch. Changes to scoring behavior after opening a locked subjective test set require a new candidate version.

## Evidence layers

1. Engineering correctness
   - deterministic output
   - bounded MOS and confidence
   - transport-delay tolerance
   - sample-rate identity
   - monotonic response to controlled severity
   - randomized crash/fuzz resistance
2. Public subjective datasets
   - held-out human MOS only
   - no fitting on the reported test partition
   - report utterance and condition-level Pearson, Spearman, RMSE, MAE and bias
3. Dedicated P.808/P.804 study
   - preregistered protocol
   - overall ACR MOS and four degradation dimensions
   - repeated subset for test-retest reliability
4. POLQA comparison
   - same locked audio pairs
   - scores generated by a lawful licensed implementation
   - human MOS remains the primary target
5. Real mobile-network field holdout
   - no fitting on these calls
   - VoLTE/VoNR and mobility conditions

## Non-inferiority decision

The numerical margin must be fixed before POLQA results for the locked set are examined. The final report will state the margin, confidence interval method, exclusions and all condition-level failures. No P.863 conformance claim will be made unless OpenVQ separately passes the official P.863 conformance requirements.
